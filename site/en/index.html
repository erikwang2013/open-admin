From zero to sign-in, four steps

Requires PHP 8.3+, Composer 2.x and MySQL 8.0+.

  1. Install dependencies

    Install Composer packages; confirm PHP extensions and database access.

  2. Configure environment

    Copy the env template locally; in production, deploy/generate-secrets.sh generates keys, TLS certificates and .env.

  3. Start the service

    This project's config/process.php listens on 8791 (stock webman uses 8787) and stays resident.

  4. Finish the wizard

    Open /install, enter database and admin details; tables, permissions and .env are created.

The installer creates runtime/install.lock. Deleting it alone is not enough: the installer refuses when an admin account already exists, so empty the database or restore it to a pre-install state first.

Local start 
composer install
cp .env.example .env
php start.php start

# Open in browser
# http://localhost:8791/install
Production (single-machine Docker Compose, 6 services) 
cd deploy
./generate-secrets.sh
docker compose up -d --build

# 6 services: nginx / app / init / mysql / redis / backup
# Secrets split per service into deploy/env/*.env
# Daily backups → deploy/data/backups (30-day retention)
# Host data and logs → deploy/data/{mysql,redis,runtime,upload} (runtime holds logs)

# Access
# https://localhost  (accept the self-signed certificate)
# Admin password: deploy/secrets/admin_password.txt
# Replace deploy/secrets/tls/ for a real domain certificate

API auth

Bearer Token

Authorization: Bearer <token>

access_token lasts 2 hours; refresh_token lasts 14 days. On 401, call refresh; never store plaintext secrets in clients.

Unified response

code 0 means success

{ "code": 0, "message": "success", "data": {} }

Errors cover 400, 401, 403, 404, 422, 429 and 500. IDs use Hashids; database keys stay hidden.

Rate limit

Read the headers

Default 60/min/IP/route; login 10/min. Responses include X-RateLimit-Limit, Remaining and Reset; read Retry-After when limited.
